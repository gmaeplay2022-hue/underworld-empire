# 《江湖》儲存與備份系統規格 V1.0

- 狀態：正式整合
- 適用範圍：瀏覽器單人版世界存檔、歷史檢查點、匯入匯出與舊存檔相容
- 儲存技術：IndexedDB
- 匯出格式：JSON

## 1. 正式決策

| 項目 | 正式規格 |
|---|---|
| 自動儲存 | 世界狀態變更停止約 1.2 秒後保存 |
| 自動檢查點 | 狀態變更建立歷史版本 |
| 歷史保留 | 每個世界最近 30 個檢查點 |
| 手動存檔 | 每個世界 10 個槽位 |
| 世界隔離 | 每個世界依世界種子與建立時間建立獨立識別 |
| 下載 | 可下載目前世界、手動存檔及歷史版本 |
| 上傳 | 先解析及驗證，再由玩家確認匯入 |
| 還原 | 還原前先保存當前世界 |
| 舊版存檔 | 保留舊 IndexedDB store，讀取時轉入新格式 |
| 雲端同步 | 本階段不實作 |

## 2. 儲存資料模型

IndexedDB 資料庫版本升至 3，保留舊版 `worlds` store，新增 `worldSaves` store。新資料使用穩定的 record ID 與 world ID，並以 worldId、savedAt 建立索引。

存檔類型：
- `auto`：每個世界一筆最新自動存檔。
- `history`：每個世界最多保留 30 筆歷史檢查點。
- `manual`：每個世界 1–10 號手動存檔。

世界識別以世界種子與建立時間組成，避免不同世界共用單一自動存檔槽。相同世界的外部備份匯入會更新該世界存檔，不同世界各自保留。

## 3. 自動儲存規則

- React 世界狀態更新後，等待約 1.2 秒無新變更再寫入，合併短時間連續操作。
- 每次有效狀態更新保存最新自動存檔並建立歷史檢查點。
- 歷史檢查點按保存時間排序，超過 30 筆時刪除最舊項目。
- 同一 record 的寫入排隊，避免較慢的舊寫入覆蓋新狀態。
- 瀏覽器關閉前不依賴非同步卸載事件作為唯一保存手段；平時自動保存是主要保護。

## 4. 手動存檔與下載

每個世界有 10 個手動存檔槽。玩家可對任意槽位保存、載入與下載。自動存檔、歷史版本也能下載 JSON 備份。檔名建議包含世界種子、遊戲天數及存檔類型。

## 5. 上傳與還原

匯入流程：
1. 玩家選擇 JSON 檔案。
2. 解析檔案格式與版本。
3. 驗證世界名稱、種子、天數、縣市、地盤與勢力等必要資料。
4. 顯示世界名稱、遊戲天數、種子、地盤、勢力及人物數量。
5. 玩家明確確認後寫入該世界的自動存檔。
6. 匯入不覆蓋其他 worldId 的資料。

還原流程：
- 玩家先選擇歷史或手動存檔。
- 還原前先將當前世界寫入自動存檔。
- 還原後切換遊戲狀態並重新讀取世界存檔清單。

## 6. 舊存檔相容

- 保留既有 IndexedDB `worlds` store，不在升級時刪除。
- 世界存檔清單讀取時，將舊版 00 自動存檔及 01–10 手動存檔轉入新 store。
- 舊資料轉入失敗時保留原資料，不自動刪除。
- JSON 匯入支援新包裝格式 `jianghu-save` V1，以及舊版直接匯出的 WorldState JSON。
- WorldState 仍透過既有 migrateWorld 執行欄位遷移。

## 7. 本機儲存限制與風險

IndexedDB 是瀏覽器本機儲存，不是雲端備份。使用者清除網站資料、瀏覽器設定檔損壞或更換裝置時，資料可能遺失。因此外部 JSON 下載是必要備份手段。雲端同步不屬於本版範圍。

## 8. 驗收標準

- [ ] 世界狀態變更後能自動保存。
- [ ] 不同世界的自動存檔互不覆蓋。
- [ ] 每個世界最多 30 個歷史檢查點。
- [ ] 每個世界有 10 個手動存檔槽。
- [ ] 自動、手動及歷史版本可下載。
- [ ] 上傳先驗證及預覽，確認後才寫入。
- [ ] 匯入不會覆蓋其他世界。
- [ ] 還原前保存當前世界。
- [ ] 舊版 IndexedDB 存檔可轉入新格式且原資料保留。
- [ ] 新舊 JSON 存檔格式皆可解析。
- [ ] 匯出後再匯入，世界種子、人物、勢力及地盤資料一致。
